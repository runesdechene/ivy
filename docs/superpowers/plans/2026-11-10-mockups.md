# Mockups automatiques — plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Générer dans IVY les mockups d'un produit Shopify (motif posé sur les photos de gabarit), les garder, les envoyer sur Shopify et les montrer sur les commandes de stock.

**Architecture:** Les règles (lecture des métachamps, choix du fichier, géométrie, planification des aperçus) sont des fonctions pures testées avec `node --test`. Le montage se fait dans le navigateur sur un `<canvas>`. Les routes API (service_role, auth Bearer) gèrent Storage, tables et Shopify GraphQL.

**Tech Stack:** Next.js 16 App Router, React 19, Mantine 7, Supabase (Postgres + Storage), Shopify Admin GraphQL `2026-10`, `fflate` (zip).

**Spec:** `docs/superpowers/specs/2026-11-10-mockups.md` (lire « Ce que la sonde a montré » et « Écarts » avant toute tâche).

## Global Constraints

- Branche `feat/mockups`. Jamais de push sur `main` ; Uriel déclenche le merge.
- `pnpm` uniquement. TypeScript strict, pas de `any`. Seule dépendance ajoutée : `fflate`.
- `APP_VERSION` (`src/config/version.ts`, actuellement `0.5.180 - Ivy`) : patch +1 dans chaque commit qui touche `src/`.
- Le dev server tourne peut-être : vérifier avec `pnpm exec tsc --noEmit`, **jamais** `pnpm build`.
- Chaque requête filtre par `shop_id`. Les nouvelles routes utilisent `authorizeRequest` + `ownsShop` (`src/lib/hub-ledger/server-auth.ts`), côté client `authFetch` (Task 3).
- Shopify : `https://${shop.shopify_url}/admin/api/2026-10/graphql.json`, jeton `shops.shopify_token`.
- Bucket `mockups` **public** (les images finissent publiques sur Shopify) ; chemins préfixés `${shopId}/`.
- Constantes : `DMAX_HAUTEUR_PX = 5906` (50 cm à 300 dpi), `DMAX_LARGEUR_PX = 4200`, `OPACITE_ENCRE = 0.75`, `TEINTES` (par teinte : couleur hex + version `CLAIR` | `SOMBRE`, valeurs d'Uriel).
- Dossier d'un motif : trois PNG 300 dpi, noir ou blanc pur sur fond transparent — `<MOTIF> CLAIR.png` (dessin pour produits clairs), `<MOTIF> SOMBRE.png` (pour produits sombres), `<MOTIF> MARQUE.png` (« Runes de Chêne <Motif> », une seule version). Variante t-shirt de la marque : en attente de la réponse d'Uriel.
- Rendu : le fichier ne donne que sa forme ; la couleur vient de `TEINTES[teinte].couleur`. Pas de mode produit.
- Métachamps : namespace `custom`, clés `fichier_d_impression` (recto) et `verso_impression` (verso).
- UI en français, mise en page des nœuds Figma `1:2` et `2:2` (skill `figma:figma-design-to-code` avant `get_design_context`), composants Mantine, styles calqués sur `src/app/ivy/inventaire/logistique/page.tsx`.
- Fichiers testés par `node --test` : imports relatifs avec extension `.ts`, pas d'alias `@/` (convention de `src/lib/hub-ledger/pin.test.ts`).

## Review Focus

1. Dossier sans le fichier CLAIR, SOMBRE ou MARQUE demandé → l'aperçu affiche « fichier manquant », il est exclu du zip et de l'envoi, rien ne plante (test `planifierApercus`, Task 2).
2. Couleur sans gabarit, ou face marque sur un gabarit sans point de marque → « gabarit manquant » / « point de marque à poser », exclu (Task 2).
3. Médias Shopify encore en traitement au rattachement → 409, le client réessaie, puis message clair (Task 6).
4. Échec en cours d'envoi → les anciens médias Shopify restent : on ne supprime qu'en dernier, après création et rattachement (Task 6).
5. Variante sans SKU ou sans métachamp d'impression → ignorée par `planifierApercus` ; si rien ne reste, message « aucune impression trouvée » (Task 2 + Task 5).

```sql
CREATE TABLE IF NOT EXISTS mockup_gabarits (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  shop_id UUID NOT NULL REFERENCES shops(id) ON DELETE CASCADE,
  modele TEXT NOT NULL,            -- SKU Shopify exact, ex. 'DRUMMER 2.0'
  couleur TEXT NOT NULL,           -- option « Couleur » Shopify, ex. 'Noir'
  face TEXT NOT NULL CHECK (face IN ('recto', 'verso')),
  photo_path TEXT NOT NULL,
  ombres_clair_path TEXT,          -- ombres pour la version CLAIR (ex-« OMBRES VR1/2 » des PSD)
  ombres_sombre_path TEXT,         -- ombres pour la version SOMBRE (ex-« OMBRES OPA/CUI »)
  cadre_x REAL NOT NULL, cadre_y REAL NOT NULL, cadre_hauteur REAL NOT NULL,  -- px sur la photo
  marque_x REAL, marque_y REAL,    -- haut-centre du logo poitrine, recto seulement
  created_at TIMESTAMPTZ DEFAULT NOW(), updated_at TIMESTAMPTZ DEFAULT NOW(),
  UNIQUE (shop_id, modele, couleur, face)
);
CREATE TABLE IF NOT EXISTS mockups (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  shop_id UUID NOT NULL REFERENCES shops(id) ON DELETE CASCADE,
  product_id UUID NOT NULL REFERENCES products(id) ON DELETE CASCADE,
  couleur TEXT NOT NULL,
  face TEXT NOT NULL CHECK (face IN ('recto', 'verso')),
  image_path TEXT NOT NULL,
  created_at TIMESTAMPTZ DEFAULT NOW(), updated_at TIMESTAMPTZ DEFAULT NOW(),
  UNIQUE (shop_id, product_id, couleur, face)
);
CREATE INDEX IF NOT EXISTS idx_mockups_product ON mockups(product_id);
```

Puis RLS activée sur les deux tables, une policy `FOR ALL` membre via `user_shops` (même forme que `color_rules` dans `006_supplier_orders.sql`), et le bucket :
`INSERT INTO storage.buckets (id, name, public) VALUES ('mockups', 'mockups', true) ON CONFLICT (id) DO NOTHING;`
