# Mockups et fichiers d'impression — plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Dans IVY : générer les mockups d'un produit Shopify, les garder, les envoyer sur Shopify, les montrer sur les commandes de stock, écrire les fichiers d'impression dans le dossier du motif, et régler par lot teintes et tailles d'impression.

**Architecture:** Toutes les règles (métachamps, choix du fichier, géométrie, profils de tailles, liste des fichiers d'impression, résolution PNG) sont des fonctions pures testées avec `node --test`. Le montage se fait dans le navigateur sur `<canvas>` ; le dossier du motif s'ouvre en lecture-écriture par `showDirectoryPicker` (Chrome/Edge). Les routes API (service_role, auth Bearer) gèrent tables, Storage et Shopify GraphQL.

**Tech Stack:** Next.js 16 App Router, React 19, Mantine 7, Supabase (Postgres + Storage), Shopify Admin GraphQL `2026-10`, `fflate` (zip).

**Spec:** `docs/superpowers/specs/2026-11-10-mockups.md` — à lire en entier avant toute tâche.

## Global Constraints

- Branche `feat/mockups`. Jamais de push sur `main` ; Uriel déclenche le merge.
- `pnpm` uniquement. TypeScript strict, pas de `any`. Seule dépendance ajoutée : `fflate`.
- `APP_VERSION` (`src/config/version.ts`, actuellement `0.5.180 - Ivy`) : patch +1 dans chaque commit qui touche `src/`.
- Le dev server tourne peut-être : vérifier avec `pnpm exec tsc --noEmit`, **jamais** `pnpm build`.
- Chaque requête filtre par `shop_id`. Nouvelles routes : `authorizeRequest` + `ownsShop` (`src/lib/hub-ledger/server-auth.ts`) ; côté client `authFetch` (Task 3).
- Shopify : `https://${shop.shopify_url}/admin/api/2026-10/graphql.json`, jeton `shops.shopify_token`. Toute écriture Shopify se teste d'abord sur un produit désigné par Uriel.
- Bucket `mockups` **public** (les images finissent publiques sur Shopify) ; chemins préfixés `${shopId}/`.
- Métachamps de variante, namespace `custom` : `fichier_d_impression` (recto), `verso_impression` (verso), `taille_d_impression`.
- Constantes : `DMAX_HAUTEUR_PX = 5906` (50 cm à 300 dpi), `DMAX_LARGEUR_PX = 4200`, `OPACITE_ENCRE = 0.75`, `PX_PAR_METRE_300DPI = 11811`.
- Teintes (couleur + version) et hauteurs des tailles d'impression sont des **réglages en base**, jamais des constantes.
- **Réduction toujours sur la hauteur, jamais sur la largeur** (Uriel) : une taille d'impression = une hauteur de planche en cm ; le dessin suit en proportion ; dans le fichier d'impression, la largeur est rognée au dessin (colonnes transparentes retirées).
- Rendu : le fichier ne donne que sa forme ; la couleur vient du réglage de la teinte. Pas de mode produit.
- Avant d'écraser un fichier dans le dossier du motif : confirmation listant les fichiers concernés.
- UI en français, mise en page des nœuds Figma `1:2` et `2:2` (skill `figma:figma-design-to-code` avant `get_design_context`), composants Mantine, styles calqués sur `src/app/ivy/inventaire/logistique/page.tsx`.
- Fichiers testés par `node --test` : imports relatifs avec extension `.ts`, pas d'alias `@/` (convention de `src/lib/hub-ledger/pin.test.ts`).

## Review Focus

1. Dossier sans le fichier CLAIR, SOMBRE ou MARQUE demandé → aperçu « fichier manquant », exclu du zip, de l'envoi et des fichiers d'impression ; rien ne plante (Task 2).
2. Teinte sans couleur ou sans version réglée → « teinte à régler » avec un lien vers Réglages, jamais une couleur par défaut silencieuse (Task 2, Task 3).
3. Médias Shopify encore en traitement au rattachement → 409, le client réessaie, puis message clair (Task 7).
4. Échec en cours d'envoi → les anciens médias Shopify restent : on ne supprime qu'en dernier (Task 7).
5. Fichiers d'impression écrits sans résolution → l'imprimeur les lirait en 72 dpi : test sur le bloc `pHYs` (Task 2), contrôle dans un logiciel d'image (Task 10).

```sql
CREATE TABLE IF NOT EXISTS mockup_gabarits (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  shop_id UUID NOT NULL REFERENCES shops(id) ON DELETE CASCADE,
  modele TEXT NOT NULL,            -- SKU Shopify exact, ex. 'DRUMMER 2.0'
  couleur TEXT NOT NULL,           -- option « Couleur » Shopify, ex. 'Noir'
  face TEXT NOT NULL CHECK (face IN ('recto', 'verso')),
  photo_path TEXT NOT NULL,
  ombres_clair_path TEXT,
  ombres_sombre_path TEXT,
  cadre_x REAL NOT NULL, cadre_y REAL NOT NULL, cadre_hauteur REAL NOT NULL,  -- px sur la photo
  marque_x REAL, marque_y REAL,    -- haut-centre de la marque, recto seulement
  created_at TIMESTAMPTZ DEFAULT NOW(), updated_at TIMESTAMPTZ DEFAULT NOW(),
  UNIQUE (shop_id, modele, couleur, face)
);
CREATE TABLE IF NOT EXISTS mockups (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  shop_id UUID NOT NULL REFERENCES shops(id) ON DELETE CASCADE,
  product_id UUID NOT NULL REFERENCES products(id) ON DELETE CASCADE,
  couleur TEXT NOT NULL,
  face TEXT NOT NULL CHECK (face IN ('recto', 'verso')),
  image_path TEXT NOT NULL,
  created_at TIMESTAMPTZ DEFAULT NOW(), updated_at TIMESTAMPTZ DEFAULT NOW(),
  UNIQUE (shop_id, product_id, couleur, face)
);
CREATE INDEX IF NOT EXISTS idx_mockups_product ON mockups(product_id);
-- Réglages : une ligne par boutique
CREATE TABLE IF NOT EXISTS mockup_reglages (
  shop_id UUID PRIMARY KEY REFERENCES shops(id) ON DELETE CASCADE,
  teintes JSONB NOT NULL DEFAULT '{}',   -- { "CUI": { "couleur": "#c9b79c", "version": "SOMBRE" }, … }
  hauteurs JSONB NOT NULL DEFAULT '{"A-SMALL":42,"B-MEDIUM":44.2,"C-LARGE":45.7,"D-MAX":50}',  -- cm de haut, mesurés sur Valkyrie
  updated_at TIMESTAMPTZ DEFAULT NOW()
);
CREATE TABLE IF NOT EXISTS mockup_profils (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  shop_id UUID NOT NULL REFERENCES shops(id) ON DELETE CASCADE,
  modele TEXT NOT NULL,
  nom TEXT NOT NULL,
  grille JSONB NOT NULL,                 -- { "XS": "B-MEDIUM", "S": "C-LARGE", "M": "D-MAX", … }
  created_at TIMESTAMPTZ DEFAULT NOW(),
  UNIQUE (shop_id, modele, nom)
);
```

Puis RLS activée sur les quatre tables, une policy `FOR ALL` membre via `user_shops` (même forme que `color_rules` dans `006_supplier_orders.sql`), et le bucket :
`INSERT INTO storage.buckets (id, name, public) VALUES ('mockups', 'mockups', true) ON CONFLICT (id) DO NOTHING;`
